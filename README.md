# TY Property: หน้าร้านและหลังร้าน

## โครงสร้างไฟล์

ไฟล์ทั้งหมดต้องอยู่ที่ระดับบนสุดของ GitHub repo (ไม่ใช่ซ้อนอยู่ในโฟลเดอร์ ty-property)

```
render.yaml          ไฟล์ตั้งค่า Render ใช้สร้างบริการทั้ง 4 ตัวพร้อมกัน
api/
  package.json       รายการไลบรารีของ API
  server.js          API และการเชื่อมต่อฐานข้อมูล Postgres
storefront/          หน้าร้าน (สาธารณะ ไม่ต้องล็อกอิน)
  index.html
  logo.png
  mark.png
admin/               หลังร้าน (ต้องใส่รหัสผู้ดูแล)
  login.html         หน้าเข้าสู่ระบบ
  index.html         หน้าจัดการรายการขาย
  mark.png
```

## ขั้นตอนการนำขึ้นระบบ

### 1. แตกไฟล์และอัปโหลดขึ้น GitHub
1. แตกไฟล์ zip ที่ได้รับ
2. เข้าไปในโฟลเดอร์ ty-property แล้วเลือกทุกอย่างข้างใน แล้วลากขึ้นไปยัง repo โดยไม่ต้องลากตัวโฟลเดอร์ ty-property ไปด้วย
3. สร้าง repo ใหม่ที่ github.com ชื่อ `ty-property` (จะตั้งเป็น Private ก็ได้) แล้วกด "uploading an existing file" ลากไฟล์ขึ้นไป แล้วกด Commit changes

### 2. สร้างบริการบน Render
1. เข้า render.com แล้วเชื่อมบัญชี GitHub
2. กด New + แล้วเลือก Blueprint เลือก repo ty-property
3. Render จะถามค่า 2 ตัว
   - `ADMIN_KEY` คือรหัสหลังร้าน ดูหัวข้อ "ตั้งรหัสหลังร้าน" ด้านล่าง
   - `ALLOWED_ORIGINS` ใส่ `*` ไว้ก่อน แล้วค่อยแก้ในขั้นตอนที่ 4
4. กด Apply แล้วรอประมาณ 5 ถึง 10 นาที จนทุกบริการขึ้นสถานะ Live

### 3. ตรวจว่า API ทำงาน
เปิด `https://ty-property-api.onrender.com/api/health` ต้องเห็นข้อความ `{"ok":true}`

### 4. ตั้งค่า ALLOWED_ORIGINS
ไปที่บริการ ty-property-api แล้วเข้าแท็บ Environment แก้ `ALLOWED_ORIGINS` เป็น URL จริงของหน้าร้านและหลังร้าน คั่นด้วยเครื่องหมายจุลภาค เช่น
`https://ty-property-store.onrender.com,https://ty-property-admin.onrender.com`
ไม่ต้องมี `/` ท้ายชื่อ แล้วบันทึก Render จะรีสตาร์ทบริการให้เอง

### 5. ตรวจ URL ของ API
- ถ้า URL ของ API เป็น `https://ty-property-api.onrender.com` ก็ไม่ต้องแก้ไฟล์ใดๆ
- ถ้าไม่ตรง (เช่น ชื่อถูกใช้ไปแล้วจน Render เติมตัวเลขต่อท้าย) ให้คัดลอก URL จาก Render แล้วค้นหาคำว่า `ty-property-api.onrender.com` ใน GitHub แก้ในไฟล์ทั้ง 3 ได้แก่ `storefront/index.html`, `admin/index.html` และ `admin/login.html` แล้ว Commit Render จะ deploy ใหม่ให้อัตโนมัติ

### 6. ใส่ข้อมูลติดต่อ
เปิด `storefront/index.html` ค้นหาคำว่า `CONTACT` แก้เบอร์โทรและลิงก์ LINE เป็นของจริง แล้ว Commit

### 7. ทดสอบหลังร้านและหน้าร้าน
1. เปิดหลังร้าน (ty-property-admin.onrender.com) ระบบจะพาไปหน้าเข้าสู่ระบบ
2. กรอกรหัสผู้ดูแล
3. เพิ่มแปลงทดสอบ 1 รายการ แล้วกดบันทึก
4. เปิดหน้าร้านและรีเฟรช ต้องเห็นรายการที่เพิ่ม
5. ลองแก้ไขและลบ แล้วตรวจว่าหน้าร้านเปลี่ยนตาม

### 8. ลบข้อมูลตัวอย่างและใส่แปลงจริง
ระบบสร้างข้อมูลตัวอย่าง 3 แปลงให้อัตโนมัติ ลบได้จากหลังร้าน แล้วเพิ่มแปลงจริงแทน

## ตั้งรหัสหลังร้าน (ADMIN_KEY)

- ใช้รหัสอย่างน้อย 16 ตัวอักษร ผสมตัวอักษรและตัวเลข
- สร้างรหัสสุ่มได้จากตัวจัดการรหัสผ่าน หรือคำสั่ง `openssl rand -hex 16` ในเทอร์มินัล
- ไม่ใส่รหัสลงในไฟล์ใดๆ และไม่ส่งให้คนที่ไม่เกี่ยวข้อง
- ถ้าลืมรหัส เข้าไปเปลี่ยนค่า ADMIN_KEY ใน Render ได้เลย

## ก่อนเปิดให้ลูกค้าใช้จริง

- ให้ทนายตรวจข้อความเรื่องบัญชีเอสโครว์และการวางเงินมัดจำในหน้าร้าน
- ตรวจตัวเลขแปลงทุกรายการ โดยเฉพาะราคาและขนาดของแปลงเจริญกรุง B-017 ที่เอกสาร TY PRIME ระบุไม่ตรงกัน
- อัปเกรดแผนของ Render เป็นแบบเสียเงิน เพราะแผนฟรีฐานข้อมูลจะหมดอายุหลัง 30 วัน และบริการจะหลับเมื่อไม่มีคนใช้
- ตรวจว่าแผนฐานข้อมูลที่เลือกมีการสำรองข้อมูลอัตโนมัติ
- ถ้าต้องการใช้โดเมนของตัวเอง เช่น `ty-property.co.th` ให้เพิ่มที่เมนู Settings > Custom Domains ของแต่ละบริการ แล้วอย่าลืมอัปเดต `ALLOWED_ORIGINS` ให้ตรงกับโดเมนใหม่

## แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| หน้าร้านขึ้น "โหลดรายการไม่สำเร็จ" | รอประมาณ 30 วินาทีแล้วรีเฟรช ถ้ายังไม่ได้ ให้เปิด `/api/health` ดูว่าตอบกลับหรือไม่ และตรวจ URL ในไฟล์ |
| ใส่รหัสแล้วขึ้น "รหัสไม่ถูกต้อง" | ค่า ADMIN_KEY ใน Render ต้องตรงทุกตัวอักษร ระวังช่องว่างหน้าหรือหลังรหัส |
| บันทึกไม่ได้หรือเห็นข้อความ CORS ใน Console | ALLOWED_ORIGINS ต้องตรงกับ URL ของหน้าเว็บ ใช้ https และไม่มี `/` ท้ายชื่อ |
| Build ล้มเหลว | เปิดดู Logs ใน Render และตรวจว่า render.yaml อยู่ที่ระดับบนสุดของ repo |
| แก้ไขไฟล์แล้วเว็บไม่เปลี่ยน | ตรวจว่า Commit ขึ้น GitHub แล้ว และรอให้ Render deploy เสร็จ บางครั้งต้องกด Hard refresh ที่เบราว์เซอร์ |
